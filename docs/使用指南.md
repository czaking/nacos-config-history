# Nacos 配置变更审计平台 · 使用指南

> 一句话:这是一个「谁在什么时候，把哪个 Nacos 配置改成了什么样」的审计台账。任何一次配置变更都能查到**操作人、时间、来源 IP、前后 diff**，并能对比任意两个历史版本。

---

## 1. 它解决什么问题

MSE Nacos 控制台本身只能看**当前配置**和有限的历史，且：

- 看不出**谁**改的（控制台显示的是 principalId，一串数字，认不出人）；
- 跨命名空间、按天维度回溯一次上线改了哪些配置很麻烦；
- 历史版本只能一个个点，无法两两 diff、无法导出。

本平台把所有命名空间的**完整版本历史**离线存下来，并自动把 principalId 解析成**真实姓名**，于是上面这些都变成一次筛选/一次点击的事。

## 2. 访问方式

**🔗 https://nacos-history.example.com**

- **内网访问**：走公司内网 / VPC（连上办公网或 VPN 即可）。外网打不开是正常的，这是内部运维工具。
- 打开即用，无需登录。

## 3. 快速上手(30 秒)

顶部两个标签页,覆盖两类需求:

| 标签页 | 回答的问题 | 典型用法 |
|---|---|---|
| **变更记录** | 「某天 / 某环境，谁改了哪些配置？」 | 排查「今天线上是不是有人动了配置」 |
| **历史对比** | 「这个配置从 A 版本到 B 版本，具体差在哪？」 | 回滚前确认改动、复盘一次变更 |

---

## 4. 「变更记录」标签页

按**天**列出配置变更流水,默认显示今天、全部命名空间、**只看人工改动**。

### 过滤条件(顶部一排)

| 过滤器 | 说明 |
|---|---|
| **日期** | 选某一天。默认今天。 |
| **命名空间** | 选具体命名空间；选了之后「环境」过滤自动忽略。 |
| **环境** | 未选具体命名空间时生效:`全部环境` / `仅生产 prod` / `仅非生产`。生产命名空间是白名单显式圈定的(含 `client-config` 这种名字不带 prod 但属生产的)。 |
| **搜索** | 按 操作人 / 配置名(DataId) / 命名空间 模糊搜。 |
| **☑ 只看人工改动** | **默认勾选**。隐藏没解析出真人姓名的账号(服务账号 / 自动化写入,如某些高频刷版本的机器人)。想看全部就取消勾选。 |

### 结果区

- **按人汇总条**(表格上方的小胶囊):`张三 · 5 项` `李四 · 2 项` —— 一眼看清当天谁动得多。
- **明细表**字段:时间、操作人、操作(新增/修改/删除)、命名空间、配置(DataId)、Group、来源 IP。
- **查看改动**:点每行最右的「查看改动」,弹窗展示**这次改动相对上一个版本的 diff**(绿加红减,右上角 `+N / -M` 行数统计)。
  - 若是该配置最早的版本,则展示首次写入的完整内容。
  - 弹窗里还有两个入口:**「在历史对比中打开 →」**(带着这对版本跳到历史对比页)、**「去 Nacos 控制台 ↗」**(直达该配置在 MSE 控制台的历史页)。

### 导出

表格下方「导出」下拉,可导出当前筛选结果:

- **CSV(Excel)** —— 带 BOM,Excel 直接正确识别中文。
- **Markdown** —— 直接粘进飞书/文档做变更周报。

文件名自动带上日期与范围,如 `nacos变更_2026-08-14_prod_人工.csv`。

## 5. 「历史对比」标签页

任意两个历史版本做 diff。三步:

1. **选命名空间** → 2. **选配置(DataId)** → 3. 在**版本时间线**里,左列选 A、右列选 B,自动出 diff。

- 默认选中**最新两个版本**对比;可任意改选 A/B 两个 radio。
- 时间线每行显示:时间、操作人、操作类型。
- diff 区顶部标 `A #版本号` `B #版本号` 和 `+N / -M`。

> 从「变更记录」的弹窗点「在历史对比中打开」进来时,命名空间/配置/版本对都会**自动带好**,省去手选。

---

## 6. 典型场景

- **「今天线上配置被谁动过？」** → 变更记录 → 日期今天 → 环境`仅生产 prod` → 一目了然,还能按人汇总。
- **「这次故障是不是配置改崩的？」** → 变更记录 → 定位到故障时间段的改动 → 「查看改动」看 diff。
- **「回滚要改回什么值？」** → 历史对比 → 选中配置 → 拿当前版本和上一个正常版本 diff,照着改回。
- **「出一份本周配置变更周报」** → 变更记录 → 逐天筛 → 导出 Markdown 拼一起。

## 7. 数据说明(重要)

- **数据来源**:MSE Nacos 实例的配置历史(`ListNacosHistoryConfigs` / `ListConfigTrack`),离线落库。
- **更新延迟**:后台每 **5 分钟**增量同步一次,所以刚改完的配置最多等 5 分钟才会出现在这里。
- **操作人解析**:principalId → 姓名 走 RAM 用户列表,每小时刷新。新入职同事的改动**首次**可能显示为数字 ID,等下一轮同步就映射成姓名。
- **覆盖范围**:17 个命名空间全部纳入。
- **「只看人工改动」**背后:某些命名空间有服务账号高频刷版本(纯噪声),默认帮你隐藏;需要审计机器人行为时取消勾选。

## 9. 已知限制

- **内网限定**:外网不可达,需连内网/VPN。
- **5 分钟延迟**:非实时,别指望改完立刻出现。
- **海量刷版本命名空间**:被机器人刷了海量版本的命名空间,极深的旧历史可能不全(多为噪声,无审计价值);常规业务命名空间数据完整。
